1. Rules of Hooks (Under-the-Hood Fiber Reason)
📌 1.1 The Two Non-Negotiable Rules
  1. Only Call Hooks at the Top Level: Kabhi bhi hooks ko if conditions, for loops, ya nested functions ke andar call mat karo.
  2. Only Call Hooks from React Functions: Sirf React Functional Components ya Custom Hooks ke andar call karo. Plain JS utility functions me call mat karo.

2. useState: Functional Updates & Lazy Initialization
📌 2.1 Lazy Initial State (Performance Optimization)

Agar initial state nikalne ke liye koi bhari calculation karni hai (jaise localStorage.getItem ko parse karna), toh direct mat likho! Varna har re-render par wo slow calculation dobara chalegi.

useState_lazy.jsxLazy Initial State
// ❌ BAD: JSON.parse runs on EVERY SINGLE re-render!
const [data, setData] = useState(JSON.parse(localStorage.getItem('saved_items')) || []);

// ✅ GOOD (Lazy Initial State): Function passes as initial value, runs ONLY on initial mount!
const [data, setData] = useState(() => {
    const saved = localStorage.getItem('saved_items');
    return saved ? JSON.parse(saved) : [];
});
3. useEffect: Dependencies, Cleanup, API Calls & Infinite Loops
📌 3.1 The 3 Modes of Dependency Array
  • useEffect(() => { ... }) (No Dependency Array): Har ek render ke baad chalta hai (Dangerous!).
  • useEffect(() => { ... }, []) (Empty Array): Sirf pehli baar mount hone par chalta hai (like componentDidMount).
  • useEffect(() => { ... }, [userId]) (With Dependencies): Pehli baar mount par chalta hai + jab bhi userId ki value badalti hai tab chalta hai.
📌 3.2 Cleanup Function: Hotel Check-out Analogy

Jab tu hotel room chhod ke jaata hai, toh AC aur lights band karke jaata hai. Varna bill aayega! Isi tarah agar tune `setInterval` ya event listener lagaya, toh component unmount hone par unhe destroy karna compulsory hai:

TimerWithCleanup.jsxCleanup Example
import { useState, useEffect } from 'react';

function LiveTimer() {
    const [seconds, setSeconds] = useState(0);

    useEffect(() => {
        const intervalId = setInterval(() => {
            setSeconds(prev => prev + 1);
        }, 1000);

        // 🧹 CLEANUP FUNCTION: Runs before component unmounts or before effect re-runs!
        return () => {
            clearInterval(intervalId); // Prevents memory leak!
        };
    }, []);

// 1. Custom Hook: useDebounce.js
import { useState, useEffect } from 'react';

export function useDebounce(value, delay = 500) {
    const [debouncedValue, setDebouncedValue] = useState(value);

    useEffect(() => {
        // Set timer to update debounced value after `delay` ms
        const handler = setTimeout(() => {
            setDebouncedValue(value);
        }, delay);

        // Cancel the timer if value changes before delay finishes!
        return () => {
            clearTimeout(handler);
        };
    }, [value, delay]);

    return debouncedValue;
}

💼 Module 3 Interview Bank (Sudheer J Style)
Rules of Hooks Senior / 8-10 LPA

Q: What are the two Rules of Hooks and what happens under the hood if you violate them?

Answer: The two rules are: (1) Only call hooks at the top level (never in loops, conditions, or nested functions), and (2) Only call hooks from React function components or custom hooks. Under the hood: React Fiber stores hooks in a singly-linked list attached to `fiber.memoizedState`. It relies entirely on the fixed, stable call order across every render. If an `if` condition skips a hook, the linked-list pointer gets misaligned, assigning the wrong state to the wrong variables and causing a fatal crash.
useMemo vs useCallback High Frequency

Q: What is the exact difference between useMemo and useCallback?

Answer: useMemo(() => fn(), deps) executes the function and memoizes the computed result (value); it only re-computes when dependencies change (ideal for heavy computations). useCallback(fn, deps) returns and memoizes the function definition itself, ensuring referential equality when passing callbacks to child components wrapped in `React.memo`.
useEffect Cleanup Core Concept

Q: When does the useEffect cleanup function execute? Does it only run on unmount?

Answer: No, it does not only run on unmount! The cleanup function runs: (1) When the component unmounts from the DOM, AND (2) Before the effect re-runs on every subsequent render when dependencies have changed. It cleans up the previous render's side effect before running the new one.
