2. The 4 Triggers That Cause a Component to Re-render
📌 2.1 Re-render kab aur kyu hota hai?
  1. State Change: Component ke andar ka useState ya useReducer setter call hona.
  2. Props Change: Parent se aane wale props ki value badalna.
  3. Parent Re-renders: Agar Parent component re-render hota hai, toh by default uske saare child components bhi re-render hote hain (chahe unke props badle ho ya na badle ho!).
  4. Context Value Change: Agar component kisi Context ko consume kar raha hai aur Provider ki value badal gayi.

5. Error Boundaries: The Crash Airbag
📌 5.1 White Screen of Death ko Rokna

React me agar kisi ek child component ke render phase me JavaScript error throw ho jaye, toh poora page white ho jaata hai. Error Boundaries ek class component hota hai jo crash hone wale component ki jagah ek graceful fallback UI dikhata hai:

ErrorBoundary.jsxClass Error Boundary
import React from 'react';

export class ErrorBoundary extends React.Component {
    constructor(props) {
        super(props);
        this.state = { hasError: false, errorMessage: "" };
    }

    static getDerivedStateFromError(error) {
        // Update state so the next render will show the fallback UI.
        return { hasError: true, errorMessage: error.message };
    }

    componentDidCatch(error, errorInfo) {
        // Log the error to an error reporting service like Sentry
        console.error("ErrorBoundary caught an error:", error, errorInfo);
    }

    render() {
        if (this.state.hasError) {
            return (

{this.state.errorMessage}

                    
                

            );
        }
        return this.props.children;
    }
}
6. Automatic State Batching (React 18 vs React 17)
📌 6.1 Dukan ke 10 Chakkar vs Ek Grocery List

Batching ka matlab hai multiple state updates ko ek sath group karke sirf ek single re-render trigger karna. React 17 me sirf React event handlers me batching hoti thi (promises aur setTimeout me 3 baar re-render hota tha). React 18 me Automatic Batching har jagah chalti hai!

Performance Senior / 10-14 LPA

Q: What are the 4 main triggers that cause a React component to re-render?

Answer: (1) Internal State Change: Calling `useState` or `useReducer` setter functions. (2) Props Change: New prop values passed from parent. (3) Parent Component Re-render: By default, when a parent re-renders, its entire child subtree re-renders unless memoized with `React.memo`. (4) Context Provider Value Change: Changes to the value prop of an active Context.
Error Boundaries High Frequency

Q: What are Error Boundaries and why can't they be written as Functional Components?

Answer: Error Boundaries catch JavaScript errors anywhere in their child component tree during rendering, lifecycle methods, and constructors, displaying a fallback UI instead of crashing the app into a white blank screen. They must be Class Components because there are currently no functional Hook equivalents for `static getDerivedStateFromError()` and `componentDidCatch()`. Note: Error boundaries do not catch errors in event handlers, async code (e.g. `setTimeout` or `fetch`), or server-side rendering.
Batching React 18 Core

Q: What is Automatic Batching in React 18, and how does flushSync alter it?

Answer: In React 18, automatic batching groups all state updates into a single re-render, whether triggered inside event handlers, promises (`fetch().then()`), `setTimeout`, or native events. If a developer requires an immediate, synchronous DOM update (e.g. to measure an element's dimensions right after a state update), React provides ReactDOM.flushSync(() => { setState(val); }) to opt out of batching and force a synchronous DOM paint.
