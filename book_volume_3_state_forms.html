1. Controlled vs Uncontrolled Components & Form Handling
📌 1.1 Definition & Tradeoffs
  • Controlled Component: The input value is driven directly by React State (value={state} + onChange). React is the "Single Source of Truth".
  • Uncontrolled Component: The input value is managed directly by the browser DOM (accessed on demand via useRef or FormData). Much faster for large forms with 50+ fields because typing does NOT trigger re-renders!
FormComparison.jsxControlled vs Uncontrolled
// 1. Controlled: Re-renders on every keystroke (Ideal for instant validation)
function ControlledInput() {
    const [email, setEmail] = useState("");
    return (
        <>
            <input value={email} onChange={e => setEmail(e.target.value)} />
            {email.length < 5 && <span>Email too short!</span>}
        </>
    );
}

// 2. Uncontrolled: Zero re-renders during typing (Uses native FormData)
function UncontrolledForm() {
    const handleSubmit = (e) => {
        e.preventDefault();
        const formData = new FormData(e.target);
        console.log("Submitted:", Object.fromEntries(formData));
    };
    return (
        <form onSubmit={handleSubmit}>
            <input name="username" defaultValue="om_sawant" />
            <button type="submit">Save</button>
        </form>
    );
}
2. Error Boundaries: Graceful UI Failure & Fallbacks
📌 2.1 Why Error Boundaries Must Be Class Components

In standard React, if a JavaScript error is thrown inside a component during rendering, the entire React component tree unmounts, showing users a blank white screen. Error Boundaries catch JavaScript errors anywhere in their child component tree, log the error, and display a fallback UI.

⚠️ Interview Must-Know: React currently has NO hook equivalent for componentDidCatch. Error Boundaries MUST be written as Class Components!

ErrorBoundary.jsxProduction Crash Protection
import React from "react";

class ErrorBoundary extends React.Component {
    constructor(props) {
        super(props);
        this.state = { hasError: false, error: null };
    }

    // Static lifecycle to update state so the next render shows fallback UI
    static getDerivedStateFromError(error) {
        return { hasError: true, error };
    }

    // Lifecycle to log errors to external monitoring service (Sentry, Datadog)
    componentDidCatch(error, errorInfo) {
        console.error("Logging to Sentry:", error, errorInfo);
    }

    render() {
        if (this.state.hasError) {
            return this.props.fallback || <h2>Something went wrong in this section.</h2>;
        }
        return this.props.children;
    }
}
export default ErrorBoundary;
3. Code Splitting, React.lazy & Suspense Streaming
📌 3.1 Reducing Initial Bundle Size

By default, Webpack/Vite bundles your entire application into a single monolithic bundle.js. Users loading your homepage must download admin dashboard code, charts, and settings before anything renders. Code Splitting splits the bundle into discrete chunks downloaded on demand.

LazyApp.jsxReact.lazy + Suspense
import React, { Suspense, lazy } from "react";

// Dynamic Import: Loaded only when user navigates to this route!
const AnalyticsDashboard = lazy(() => import("./AnalyticsDashboard"));

function App() {
    return (
        <div>
            <h1>Main Portal</h1>
            <Suspense fallback={<div className="spinner">Loading Analytics Chunk...</div>}>
                <AnalyticsDashboard />
            </Suspense>
        </div>
    );
}

💻 4.2 Zustand Production Store Pattern
store/useCartStore.jsZustand Minimal Store
import { create } from "zustand";

export const useCartStore = create((set) => ({
    items: [],
    addItem: (item) => set((state) => ({ items: [...state.items, item] })),
    removeItem: (id) => set((state) => ({ items: state.items.filter(i => i.id !== id) })),
    clearCart: () => set({ items: [] })
}));

// Usage in component (Select only needed state to prevent re-renders!):
function CartBadge() {
    const count = useCartStore((state) => state.items.length); // Selector!
    return <span>Cart: {count}</span>;
}
