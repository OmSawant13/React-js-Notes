Core React Fresher / 4-6 LPA #1

Q1: What is React, and what are its major features?

Simple Desi Samjhaav: React ek frontend JavaScript library hai (framework nahi!) jise Facebook ne banaya tha interactive UI banane ke liye.
Top 4 Major Features:
  • Declarative UI: Tumhe browser ko ye nahi batana padta ki DOM me button dhoondo aur text change karo. Tum sirf State define karte ho (UI = f(State)), DOM apne aap update ho jata hai.
  • Virtual DOM (VDOM): Real DOM slow hota hai, isliye React memory me ek lightweight JS copy (VDOM) rakhta hai aur sirf wahi part change karta hai jo badla hai (Reconciliation).
  • Component-Based Architecture: Poori website chhote-chhote reusable Lego blocks (Components) me banti hai jaise <Navbar />, <Button />.
  • Unidirectional Data Flow: Data hamesha Parent se Child ki taraf niche flow hota hai via Props. Isse debugging predictable rehti hai.
Library vs Framework Basic Interview #2

Q2: What is the difference between a Library (React) and a Framework (Angular / Vue)?

Key Difference (Inversion of Control):
  • Library (React): You are in control! React sirf 'View' layer handle karta hai. Routing (React Router), State Management (Zustand/Redux), aur API fetching (Axios/React Query) ke liye tum apni marzi ka tool choose karte ho. You call the library.
  • Framework (Angular): The Framework is in control! Angular me routing, forms, HTTP client, dependency injection sab kuch pehle se fixed hota hai. Unke strict rules aur folder structure me hi code likhna padta hai. The framework calls your code.
JSX Internals Core Concept #3

Q3: What is JSX, and why can't web browsers read it directly?

Answer: JSX (JavaScript XML) ek syntax extension hai jo hume JS ke andar HTML-like code likhne deta hai.
Why browser can't read it: Browsers sirf standard ECMAScript (JS) samajhte hain, JSX koi valid JS syntax nahi hai. Isliye Babel ya SWC compiler JSX ko compile karke standard JS function calls me badal deta hai:
// JSX: <h1 className="title">Hello</h1>
// Compiled: React.createElement('h1', { className: 'title' }, 'Hello');
Ye function ek plain JavaScript object (React Element) return karta hai jise browser VDOM me process karta hai.
Element vs Component Interview Trap #4

Q4: What is the exact difference between a React Element and a React Component?

Key Answer:
  • React Element: Ye ek immutable plain JavaScript object hai jo screen par render hone wale DOM node ko describe karta hai (e.g. const elem = <h1>Hi</h1>;). Iska $$typeof: Symbol.for('react.element') hota hai. Isse directly call nahi kiya ja sakta.
  • React Component: Ye ek JavaScript function ya class hai jo props accept karta hai aur ek React Element return karta hai (e.g. function UserCard(props) { return <div>...</div>; }). Component reusable blueprint hota hai, jabki Element ek runtime snapshot hota hai.

State Immutability Senior / 6 LPA #6

Q6: Why should we NEVER mutate state directly (e.g., state.count = 5)?

Answer: Agar tum state.count = 5 likhoge:
  1. No Re-render Triggered: React tab tak re-render trigger nahi karta jab tak tum setState() ya setCount() na call karo. UI par purana data hi dikhta rahega.
  2. Shallow Comparison Broken: React Fiber reconciliation me state ka memory reference check karta hai (Object.is(oldState, newState)). Directly mutate karne par purana aur naya memory address same rehta hai, jisse React samajh hi nahi pata ki data change hua hai.
  3. Time Travel & Optimization Loss: Undo/Redo aur React DevTools debugging completely break ho jaati hai. Hamesha state ka naya copy return karo: setUser(prev => ({ ...prev, count: 5 })).
Synthetic Events Core Concept #7

Q7: What are Synthetic Events in React, and how are they different from Native DOM Events?

Answer: SyntheticEvent React ka ek cross-browser wrapper hai jo native browser DOM events (MouseEvent, KeyboardEvent) ko wrap karta hai.
Why it exists: Har browser (Chrome, Safari, Firefox, Edge) ke native event handling me subtle differences hote hain. SyntheticEvents ensure karta hai ki aapka onClick har browser me exactly 100% same behave kare (W3C spec compliant).
Event Delegation: React 17+ me React har ek individual button par listener lagane ke bajaye root container (#root) par ek single event listener lagata hai aur events ko bubble karke capture karta hai (huge memory optimization!).

Q8: What is the 'key' prop in React, and why does using the array index as a key cause bugs?

Answer: key ek special string attribute hai jo list items ko stable identity deta hai taaki React reconciliation diffing me pehchan sake ki kaun sa item add, remove ya reorder hua hai.
⚠️ The Array Index Trap:
Agar tum key={index} use karoge aur user list ke top se ek item delete karega:
Item #2 ka index ab 0 ho jayega! React sochega pehla item abhi bhi zinda hai aur sirf aakhri item gayab hua hai. Isse uncontrolled inputs (text boxes, checkboxes) wrong rows par chipak jaate hain aur state mismatch ho jati hai.
Rule: Hamesha database ki unique id use karo: key={todo.id}.
Fragments Basic Interview #9

Q9: What are React Fragments (<>...</>), and why should you use them over extra <div> tags?

Answer: React me har component ko ek single root element return karna hota hai. Agar hum extra <div> lagayenge to:
1. DOM Tree Bloat: Unnecessary nested HTML tags memory aur CSS styling ko pollute karte hain.
2. CSS Grid / Flexbox Breakage: Flexbox me parent-child direct relationship chahiye hoti hai. Extra div lagane se layouts toot jaate hain.
Solution: <React.Fragment>...</React.Fragment> (ya shortcut <>...</>) multiple children ko group karta hai bina real DOM me koi physical node add kiye!
Controlled vs Uncontrolled High-Frequency #10

Q10: What is the difference between Controlled and Uncontrolled Components in React forms?

Answer:
  • Controlled: Input ki value React State se drive hoti hai (value={name} aur onChange={e => setName(e.target.value)}). Har keystroke par React render hota hai. Best for real-time validation, dynamic disabling.
  • Uncontrolled: Input ki value browser DOM khud manage karta hai. React sirf form submit hone par useRef() ya new FormData(e.target) se value read karta hai. Best for massive forms (50+ inputs) jahan har keystroke par re-render nahi chahiye.

Q11: What is a Pure Component in React, and what is its functional component equivalent?

Answer: Class components me React.PureComponent automatically shouldComponentUpdate() implement karta hai jo props aur state ka shallow comparison karta hai. Agar props aur state same hain, to component re-render nahi hota.
Functional Equivalent: Functional components me iska exact equivalent hai React.memo(Component)!
Portals Senior / 8 LPA #12

Q12: What are React Portals (ReactDOM.createPortal), and what problem do they solve?

Answer: ReactDOM.createPortal(children, domNode) aapko kisi component ke JSX ko uske parent DOM hierarchy se bahar kisi doosre DOM element (jaise document.body) me render karne deta hai.
Real Problem Solved: Modals, Dialogs, Tooltips, aur Popups! Agar parent container par overflow: hidden ya z-index: 1 laga hai, to modal screen par kat jata hai ya dhang se pop out nahi hota. Portal se modal <body> ke direct child me render hota hai lekin React context aur event bubbling parent ke sath intact rehti hai!

Security / XSS Security Round #14

Q14: How does React prevent Cross-Site Scripting (XSS) attacks by default?

Answer: 1. Automatic Escaping: Jab tum JSX me <h1>{userInput}</h1> likhte ho, React har string ko render karne se pehle sanitize/escape karta hai. Agar input me <script>alert('hacked')</script> hoga, to wo execute nahi hoga, balki safe plain text ban jayega.
2. Symbol Security ($$typeof): React elements ke andar $$typeof: Symbol.for('react.element') hota hai. Hacker JSON injection se mock React component inject nahi kar sakta kyunki JSON me Symbol data type exist hi nahi karta.
Note: React me XSS sirf tab possible hota hai agar tum galti se dangerouslySetInnerHTML={{ __html: userInput }} use kar lo bina sanitize kiye!
Reconciliation Senior / 10 LPA #15

Q15: Explain the React Diffing Algorithm and its two main assumptions.

Answer: Theoretical tree diffing $O(n^3)$ hota hai. React ne isko linear $O(n)$ heuristic banaya do core assumptions par:
  1. Different Element Types: Agar do elements ka tag type alag hai (e.g. <div> replaced by <span>), React purane poore subtree ko destroy kar deta hai aur scratch se naya tree mount karta hai.
  2. Keys for List Identification: Dynamic lists me React key attribute dekh kar pehchanta hai ki kaun sa element sirf aage-peeche shift hua hai, taaki purane DOM nodes ko reuse kiya ja sake.
Hooks Introduction Core Concept #16

Q16: What are React Hooks, and why were they introduced in React 16.8?

Answer: Hooks functions hain jo hume functional components ke andar state aur React lifecycle features use karne dete hain.
Why Facebook introduced Hooks (Class Components ke 3 bado dard):
  • Wrapper Hell: Logic reuse karne ke liye Higher Order Components (HOC) aur Render Props use karna padta tha, jisse JSX tree me 20 nested wrappers ban jaate the.
  • Huge Confusing Lifecycles: Ek hi componentDidMount ke andar data fetch, event listener, aur timer set karna padta tha. Unrelated logic mix ho jata tha.
  • 'this' Keyword Confusion: Class methods me this.handleClick.bind(this) likhna padta tha, jo JS beginners ke liye bohot confusing tha.
Rules of Hooks Crucial Interview #17

Q17: What are the two Rules of Hooks, and WHAT happens under the hood if you violate them?

The Two Non-Negotiable Rules:
  1. Only Call Hooks at the Top Level: Kabhi bhi hooks ko if conditions, for loops, ya nested functions ke andar call mat karo.
  2. Only Call Hooks from React Functions: Sirf React functional components ya Custom Hooks ke andar call karo (plain JS utility functions me nahi).
Under-the-Hood Reason:
React Fiber node par hooks ka koi 'name' nahi hota! React hooks ko ek Singly Linked List me store karta hai (fiber.memoizedState) aur har render par sequentially pointer aage badhata hai (Hook 1 ➡️ Hook 2 ➡️ Hook 3). Agar tumne if (condition) useState() likha aur kisi render me wo condition false ho gayi, to poori linked list ka order hil jayega, aur React galat state ko galat variable me assign kar dega, crashing the app!
useState Batching Senior / 8 LPA #18

Q18: What is Automatic Batching in React 18, and how did it work in React 17?

Answer: Batching ka matlab hai multiple state updates ko ek sath group karke sirf ek single re-render trigger karna, taaki UI bar-bar na jhatke.
  • React 17 (Partial Batching): Sirf React event handlers (jaise onClick) ke andar batching hoti thi. Agar state updates setTimeout, fetch().then(), ya native promises ke andar the, to har ek setState alag se poora component re-render karta tha!
  • React 18 (Automatic Batching): Chahe state updates promise me ho, timer me ho, ya event me ho — React 18 automatically sabhi updates ko group karke exactly 1 re-render karta hai!
Stale State Trap High-Frequency #19

Q19: Why does calling setCount(count + 1) three times in a row only increment the count by 1?

Answer (The Stale Closure Trap):
function handleClick() { setCount(count + 1); setCount(count + 1); setCount(count + 1); }
Jab ye function render hota hai, closure ke andar count ki value 0 par lock hoti hai. Teeno calls actually setCount(0 + 1) run kar rahe hote hain! Aakhri call pehle do ko overwrite kar deta hai, isliye count sirf 1 banta hai.
The Fix (Functional Updates):
setCount(prev => prev + 1); setCount(prev => prev + 1); setCount(prev => prev + 1);
Functional update me React queue me se fresh pending state pass karta hai, isliye count 3 banta hai.
useEffect Lifecycles Core Concept #20

Q20: How does useEffect mimic componentDidMount, componentDidUpdate, and componentWillUnmount?

Answer:
  • componentDidMount (Initial mount only): Empty dependency array pass karo: useEffect(() => { ... }, []); (Sirf first render ke baad chalta hai).
  • componentDidUpdate (On specific state/prop change): Array me variable pass karo: useEffect(() => { ... }, [userId]); (Sirf userId badalne par chalta hai).
  • componentWillUnmount (Cleanup on destroy): Cleanup function return karo: useEffect(() => { return () => { cleanupTimer(); }; }, []);.
  • Every Render (No array): Agar dependency array pass hi na karo: useEffect(() => { ... }); (Har ek re-render ke baad chalega).
useEffect Cleanup Senior / 8 LPA #21

Q21: When does the useEffect cleanup function execute? Does it ONLY run on unmount?

Interview Trap Answer: NO! Cleanup function sirf unmount par nahi chalta! Ye do time chalta hai:
  1. Before EVERY re-run of the effect: Agar dependencies change hui hain, to React pehle purane render ka cleanup function chalata hai, taaki purane listeners ya subscriptions remove ho sakein, aur uske baad naya effect run karta hai.
  2. On Component Unmount: Jab component screen se destroy hota hai.
Race Conditions Senior / 10 LPA #22

Q22: How do you handle Network Race Conditions in useEffect using AbortController?

Problem: Agar user tab A click karta hai aur turant tab B click karta hai, network latency ki wajah se tab A ka response agar der se aaya, to screen par tab B ke bajaye tab A ka purana data chipak jayega (Race Condition).
The Solution (AbortController):
useEffect(() => {
    const controller = new AbortController();
    fetch(`/api/data/${tabId}`, { signal: controller.signal })
        .then(res => res.json())
        .then(data => setData(data))
        .catch(err => { if (err.name !== 'AbortError') console.error(err); });

    return () => controller.abort(); // Cancels previous pending HTTP call!
}, [tabId]);
useMemo vs useCallback High-Frequency #23

Q23: What is the exact difference between useMemo and useCallback? Give practical examples.

Key Difference:
  • useMemo: Function ke return value (calculated result) ko cache karta hai taaki heavy calculation dobara na chale.
    const totalSalary = useMemo(() => computeHeavyMath(list), [list]);
  • useCallback: Function ke definition (memory reference) ko cache karta hai taaki child component ko naya function reference na mile aur child re-render hone se bach sake.
    const handleDelete = useCallback((id) => { deleteItem(id); }, []);
Simple Rule: useCallback(fn, deps) is equivalent to useMemo(() => fn, deps)!

useLayoutEffect Senior / 10 LPA #25

Q25: What is the exact difference between useLayoutEffect and useEffect? When should useLayoutEffect be used?

Execution Timing Difference:
  • useLayoutEffect: DOM update hone ke turant baad SYNCHRONOUSLY chalta hai, browser ke screen par paint karne se pehle. Ye browser paint ko block karta hai.
  • useEffect: Browser ke screen par pixels paint karne ke baad ASYNCHRONOUSLY chalta hai. Ye UI ko block nahi karta.
When to use useLayoutEffect: Sirf tab jab aapko DOM measure karke (e.g. tooltip height, modal position, scroll offset) turant styles adjust karni ho, taaki user ko aadhi second ka visual flicker / UI jump na dikhe.
useContext Trap Senior / 9 LPA #26

Q26: What is the Context Re-render Pitfall, and how do you optimize it?

The Pitfall: Jab Context Provider ki value object update hoti hai, to har wo component jo useContext(MyContext) call karta hai re-render hota hai, chahe wo us context ki sirf ek chhoti si un-changed property consume kar raha ho! React.memo bhi is re-render ko rok nahi sakta.
Optimization (Context Splitting Pattern):
Frequently changing state (e.g. active tab, theme) aur rarely changing state/dispatch functions (e.g. login, logout) ko do alag-alag Contexts me split karo (AuthDataContext and AuthDispatchContext).
useReducer vs useState Architectural #27

Q27: When should you prefer useReducer over useState?

Prefer useReducer when:
  1. Jab state logic complex ho aur ek state doosre multiple state fields par depend karti ho (e.g. multi-step wizard form, checkout cart).
  2. Jab agla state purane state ke complex transitions par depend karta ho (finite state machine: IDLE -> LOADING -> SUCCESS / ERROR).
  3. Testing: Reducer pure function hota hai jise bina kisi React UI ke independently unit test kiya ja sakta hai.

Q28: What is useTransition in React 18, and how does it prevent UI freezing during heavy updates?

Answer: useTransition() ek hook hai jo aapko kisi state update ko Non-Urgent Transition mark karne deta hai.
React updates ko 2 categories me baant-ta hai:
  • Urgent Updates: Typing, clicking, buttons (needs instant response).
  • Transition Updates: Large chart rendering, 5,000 item list filtering.
Jab aap startTransition(() => setList(filtered)) likhte ho, React background me list filter karta hai. Agar user beech me input me koi doosra letter type kar deta hai, to React transition ko interrupt / pause kar deta hai taaki input field smooth rahe!
Custom Hooks Core Skill #29

Q29: What is a Custom Hook, and what are the naming conventions and rules for creating one?

Answer: Custom Hook ek normal JavaScript function hota hai jiske andar doosre React hooks (useState, useEffect) use hote hain. Iska purpose component se stateful logic extract karke reusable banana hota hai.
Conventions: 1. Name hamesha use se start hona chahiye (e.g. useFetch, useAuth) taaki React ka ESLint linter enforce kar sake ki Rules of Hooks follow ho rahe hain.
2. Har component jo custom hook call karta hai, use state ki apni independent copy milti hai (state shared nahi hota, sirf logic shared hota hai!).
Error Boundaries Crucial Interview #30

Q30: What are Error Boundaries in React, and why can't they be written as Functional Components?

Answer: Error Boundary ek React component hai jo apne child tree me aane wale JS errors ko catch karta hai aur white blank screen ke bajaye ek sundar Fallback UI dikhata hai.
Why it MUST be a Class Component: Error boundary banne ke liye component ko do specific lifecycle methods implement karne hote hain:
  • static getDerivedStateFromError(error): State update karta hai fallback UI render karne ke liye.
  • componentDidCatch(error, errorInfo): Error ko Sentry ya monitoring service me log karta hai.
React team ne abhi tak in dono lifecycles ka koi functional hook release nahi kiya hai, isliye Error Boundaries aaj bhi class components me hi likhe jaate hain!
HOC vs Custom Hooks Architecture #31

Q31: What is a Higher-Order Component (HOC), and why have Custom Hooks largely replaced them?

Answer: HOC ek function hai jo ek component ko argument me leta hai aur naye data/props ke sath ek wrapped component return karta hai: const Enhanced = withAuth(ProfilePage);.
Why Custom Hooks replaced HOCs: 1. Props Collision: HOC props inject karta hai jisse pata nahi chalta kaun sa prop kahan se aaya, aur prop names overwrite ho jaate the.
2. Wrapper Hell: 4 HOC lagane se React DevTools me 40 nested layers ban jaati thi.
3. Custom Hooks bina kisi JSX wrapping ke clean, direct state return karte hain.
React Router v6 Routing Master #32

Q32: What is the role of in React Router v6, and how does nested routing work?

Answer: <Outlet /> ek placeholder component hai jo parent layout route ke andar child route ke component ko render karta hai.
Why it's awesome: Agar tumhara /dashboard par Header aur Sidebar hai, to /dashboard/settings aur /dashboard/profile par navigate karne par Header aur Sidebar KABHI remount ya re-render nahi hote! Sirf <Outlet /> ke andar ka chhota sa page swap hota hai, saving huge CPU cycles.

Q33: How do you implement Protected Routes and Auth Guards in React Router v6?

Answer: Ek wrapper component banaya jata hai jo authentication token check karta hai:

Redux Core State Management #34

Q34: What are the 3 Core Principles of Redux, and what problem does it solve?

The 3 Unbreakable Principles of Redux:
  1. Single Source of Truth: Poori application ka global state ek single JavaScript object tree ke andar (Store) store hota hai.
  2. State is Read-Only: State ko direct modify nahi kar sakte. State change karne ka ek hi rasta hai: Dispatch an Action (plain object describing what happened: { type: 'ADD_ITEM', payload: item }).
  3. Changes are made with Pure Functions: Actions ko accept karke naya state calculate karne ka kaam Reducers (pure functions) karte hain. (No side effects, no mutations).
Redux Toolkit (RTK) Senior / 8 LPA #35

Q35: Why was Redux Toolkit (RTK) introduced, and why does it allow writing state.count++ in reducers?

Answer: Legacy Redux me bohot zyada boilerplate tha (action types, action creators, immutable spread operators, switch statements). Redux Toolkit (RTK) createSlice() introduce karta hai jo ye sab automate kar deta hai.
Why 'state.count++' works in RTK:
RTK internally Immer library use karta hai! Jab aap state.count++ likhte ho, Immer ek temporary draft state maintain karta hai aur background me ek completely new, safely cloned immutable object generate kar deta hai. Code likhne me simple lagta hai par immutability 100% preserve rehti hai!
Zustand vs Redux Modern Frontend #36

Q36: Why are top modern frontend teams preferring Zustand over Redux?

Key Advantages of Zustand:
  • Zero Boilerplate: Na koi <Provider> wrapper chahiye, na complex slices/reducers. Ek simple hook me store ban jata hai: const useStore = create((set) => ({ count: 0 }));.
  • Fine-Grained Selectors: useStore(s => s.user) likhne par component sirf user change hone par render hoga.
  • Tiny Bundle Size: Redux Toolkit (~12KB) ke muqable Zustand sirf ~1KB hai!
React Query vs Redux High-Frequency #37

Q37: What is the difference between Client State and Server State? Why should you not store API data in Redux?

Key Difference:
  • Client State: Jo sirf browser ke paas hota hai (e.g. modal open hai ya nahi, dark mode toggle). Iske liye Zustand / Redux best hai.
  • Server State: Jo backend database me rehta hai aur HTTP se fetch hota hai (e.g. user list, products). Ye remote hota hai, asynchronous hota hai, aur doosre users ke changes se stale ho sakta hai.
Why TanStack React Query is better for Server State: Agar tum Redux me API data rakhoge to caching, background refetching, deduplicating multiple identical calls, loading/error states, aur pagination ka 200 lines ka boilerplate khud likhna padega. React Query ye sab 1 line me handle karta hai (useQuery(['jobs'], fetchJobs))!
Re-rendering Triggers Performance Core #38

Q38: What are the 4 triggers that cause a React component to re-render?

The 4 Triggers:
  1. Internal State Change: useState ya useReducer ka setter call hone par.
  2. Parent Component Re-render: Jab parent render hota hai, to by default uske saare children recursively render hote hain, chahe unke props change hue ho ya na hue ho!
  3. Props Change: Parent se aane wale props ki value badalna.
  4. Context Value Change: Context Provider ki value change hone par har consumer render hota hai.
React.memo Gotcha Senior / 10 LPA #39

Q39: Explain why passing an inline object or inline function breaks React.memo.

The Mechanism: React.memo props ka shallow comparison (===) karta hai.
In JavaScript: { a: 1 } === { a: 1 } is FALSE! Kyunki har render par memory heap par naya reference pointer banta hai.
Agar parent har render par <Child user={{ id: 1 }} onClick={() => {}} /> bhej raha hai, to React.memo dekhega ki dono props ke memory addresses alag hain aur child ko zabardasti re-render kar dega! Isse bachne ke liye object ko useMemo aur function ko useCallback me wrap karna mandatory hai.
Virtualization High Scale / 14 LPA #40

Q40: What is List Virtualization (Windowing), and how does react-window optimize massive lists?

The Scale Problem: 10,000 DOM elements render karne par browser 800MB RAM use karta hai aur scroll karte waqt 60FPS se gir kar 5FPS ho jata hai.
Virtualization Solution: User ke screen viewport me ek time par sirf 10–15 rows dikh sakti hain. Virtualization library (react-window) sirf un 15 rows ko physical DOM me render karti hai. Jaise-jaise user scroll karta hai, upar se nikle hue DOM nodes ko recycle karke niche render kar diya jata hai. DOM node count hamesha ~15 par constant rehta hai, chahe list me 10 Lakh items kyun na hon!
Debounce vs Throttle Core Interview #41

Q41: What is the difference between Debouncing and Throttling? Give real frontend use cases.

Key Difference:
  • Debouncing: Function tab tak execute nahi hoga jab tak user events trigger karna band karke X ms ka pause na le le. Har naye event par purana timer reset ho jata hai.
    Use Case: Search Bar autocomplete! User ke type karne ke 400ms baad ek single API call jaati hai.
  • Throttling: Ek fixed time interval (e.g. 200ms) me function ko at most sirf ek baar execute hone deta hai, chahe user 1,000 baar click ya scroll kare.
    Use Case: Infinite Scroll / Window Resize listener! Scroll event har millisecond fire hota hai, throttling se browser choke nahi hota.

DOM Comparison Core Interview #45

Q45: What is the difference between Virtual DOM, Shadow DOM, and Real DOM?

The 3 DOMs Decoded:
  • Real DOM: Browser ka actual tree structure (HTML elements). Real DOM me direct manipulation (jaise document.getElementById().appendChild()) bohot slow hota hai kyunki browser ko poora Layout, Reflow, aur Repaint calculate karna padta hai.
  • Virtual DOM (VDOM): React dwara banaya gaya lightweight in-memory JavaScript object tree. React changes ko pehle VDOM me calculate karta hai (Diffing) aur minimum Real DOM updates batch karta hai.
  • Shadow DOM: Browser ka native feature (Web Components) jo DOM tree ke ek hisse ko encapsulate (isolate) karta hai. Shadow DOM ke andar ke CSS styles bahar ke elements ko affect nahi karte (jaise <video> ke native controls).
Summary: Real DOM = Actual building, Virtual DOM = Blueprint in memory, Shadow DOM = Gated isolated room inside the building.

Why Asynchronous:

Fiber Architecture Senior / 12-16 LPA #47

Q47: What is React Fiber and how does it differ from the old Stack Reconciler?

The Big Evolution (React 15 vs React 16+):
  • Old Stack Reconciler (React 15): Recursive algorithm use karta tha. Ek baar tree diffing shuru hui, to poora component tree process hone tak JavaScript main thread block ho jata tha. Agar tree bada ho, to user clicks aur keyboard input freeze ho jate the (Frame drops / 60 FPS drop).
  • Fiber Reconciler (React 16+): Reconciler ko completely re-write kiya gaya. Fiber ek virtual stack frame hai. Har component ek 'Fiber Node' ban jata hai jo Doubly-Linked List structure me connected rehta hai (child, sibling, return pointers).
Superpowers of Fiber:
  • Time-Slicing: React heavy work ko chhote-chhote 5ms chunks me todta hai. Agar user click kare, to render ko PAUSE karke pehle click handle karta hai, fir wapas resume karta hai!
  • Priority-based Scheduling: Animations aur User Typing ko highest priority milti hai, jabki background data fetch ko lowest.

Comparison Types Deep Concept #61

Q61: What is Shallow Comparison vs Deep Comparison in React? Where does React use shallow comparison?

Shallow vs Deep Comparison:
  • Shallow Comparison (Fast - O(1)): Primitive types ke liye direct equality check karta hai (a === b). Objects aur Arrays ke liye sirf unka memory reference check karta hai, andar ke nested properties check nahi karta.
  • Deep Comparison (Slow - O(N)): Object ke har ek nested key, sub-object, aur array ko recursively loop karke compare karta hai. Large objects me ye CPU ko choke kar deta hai.
Where React uses Shallow Comparison:
  • React.memo(Component) props compare karne ke liye.
  • Hook dependency arrays (useEffect, useMemo, useCallback).
  • useState ka bail-out check (Object.is(prevState, nextState)).

JWT Interceptors Production Architecture / 10-12 LPA #63

Q63: How do you handle automatic JWT token refresh on 401 Unauthorized responses in a React application?

Production Token Rotation Flow:
Axios Response Interceptors use karke 401 errors ko intercept kiya jata hai: 
import axios from 'axios';

const api = axios.create({ baseURL: '/api' });

api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;
    // If 401 and request hasn't been retried yet
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;
      try {
        // Call refresh endpoint using httpOnly cookie
        const res = await axios.post('/api/auth/refresh');
        const newAccessToken = res.data.accessToken;
        
        // Update header and retry original failed request
        originalRequest.headers['Authorization'] = `Bearer ${newAccessToken}`;
        return api(originalRequest);
      } catch (refreshError) {
        // Refresh token expired too -> redirect to /login
        window.location.href = '/login';
        return Promise.reject(refreshError);
      }
    }
    return Promise.reject(error);
  }
);
