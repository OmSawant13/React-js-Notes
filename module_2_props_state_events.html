1. Props and Prop Destructuring
📌 1.1 Definition & Real Purpose

Props (Properties): Jab Parent component apne Child component ko koi data bhejna chahta hai, toh wo Props use karta hai. Yeh bilkul HTML ke attributes jaisa hota hai jaise <img src="..." alt="..." />, lekin yahan hum numbers, strings, objects, arrays, aur functions sab bhej sakte hain!

Destructuring: Puraane zamaane me log har jagah props.name, props.age likhte the. Modern JavaScript me hum direct parameters ke andar curly braces { name, age } laga kar props ko destructure kar lete hain. Code 5 guna clean ho jata hai!

UserCard.jsxProps & Destructuring
// ❌ PURAANA TAREEEQA (Lamba aur repetitive)
function OldUserCard(props) {
    return <div>Hello, {props.name}! You are {props.age} years old.</div>;
}

// ✅ MODERN PRODUCTION TAREEEQA (Clean Destructuring)
function UserCard({ name, age, city }) {
    return (
        <div className="user-badge">
            <h3>{name}</h3>
            <p>Age: {age} | City: {city}</p>
        </div>
    );
}

// Parent Component Call:
<UserCard name="Aman Gupta" age={24} city="Delhi" />

3. Props vs State: The Ultimate Breakdown
📌 3.1 Apna Paisa vs Baap ki Pocket Money
💰 Desi Analogy: Props vs State

• Props: Baap ki di hui Pocket Money! Parent deta hai, Child isko badal nahi sakta (Read-Only).
• State: Tera khud ka Bank Account! Tu jab chahe kama sakta hai, uda sakta hai (setBalance()), aur tere balance badalne par teri lifestyle (UI) re-render ho jaati hai!

Criteria Props State
Ownership Parent component ke paas hoti hai Component ka khud ka private data hota hai
Mutability Immutable! Child ise change nahi kar sakta Mutable via Setter! (setCount())
Passing Parent se Child me pass hota hai Component ke andar hi rehta hai
Re-render Trigger Jab Parent naye props bhejta hai Jab setter function call hota hai
4. One-Way Data Flow (Unidirectional)
📌 4.1 Paani Hamesha Pahad se Nadi ki Taraf Bahta Hai

React me data hamesha Parent ➡️ Child ki taraf niche flow hota hai via Props. Kabhi bhi Child direct Parent ki state nahi badal sakta. Isse debugging predictable hoti hai: agar screen par koi bug aaya, toh hume pata hota hai ki data upar se kahan se aa raha hai!

Child se Parent me data kaise bhejte hain? Parent ek Callback Function as a prop Child ko deta hai. Jab Child me koi event hota hai, wo us function ko data dekar call kar deta hai!

5. useState Hook: Component ki Yaaddasht (Memory)
📌 5.1 Syntax aur Internal Working

Normal JavaScript function execution ke baad apne local variables ko bhool jaata hai (Garbage Collection). useState React Fiber node par data ko preserve karke rakhta hai taaki re-render hone par bhi data zinda rahe!

Counter.jsxBasic useState
import { useState } from 'react';

function Counter() {
    // [currentValue, setterFunction] = useState(initialValue);
    const [count, setCount] = useState(0);

    return (
        <div>
            <h2>Current Count: {count}</h2>
            <button onClick={() => setCount(count + 1)}>Increment ➕</button>
            <button onClick={() => setCount(count - 1)}>Decrement ➖</button>
            <button onClick={() => setCount(0)}>Reset 🔄</button>
        </div>
    );
}
6. State Updates and Re-rendering Cycle
📌 6.1 State badalti hai toh kya hota hai?
  1. Jab tu setCount(5) call karta hai, React is update ko ek queue me daal deta hai.
  2. React component function ko dobara execute karta hai (Re-render Phase).
  3. Function naya JSX return karta hai.
  4. React naye aur purane Virtual DOM ko compare karta hai (Diffing).
  5. Real DOM me sirf wahi number update hota hai (Commit Phase).
7. Previous State Updates (Functional Updates)
📌 7.1 Ghajini Stale Closure Trap aur uska Ilaaj

Agar tu ek function ke andar 3 baar setCount(count + 1) likhega, toh count 3 nahi badhega, sirf 1 badhega! Kyunki us render me count purana tha.

SafeStateUpdate.jsxFunctional Updates
// ❌ BUGGY: Stale closure captures count as 0 in all 3 calls!
const badAddThree = () => {
    setCount(count + 1); // 0 + 1
    setCount(count + 1); // 0 + 1
    setCount(count + 1); // 0 + 1 -> Final result: 1!
};

// ✅ SAFE & INDUSTRY STANDARD: Functional Update
const goodAddThree = () => {
    setCount(prev => prev + 1); // prev is 0 -> becomes 1
    setCount(prev => prev + 1); // prev is 1 -> becomes 2
    setCount(prev => prev + 1); // prev is 2 -> becomes 3! Final result: 3!
};
8. Event Handling in React
📌 8.1 CamelCase, SyntheticEvents & Parameter Passing

HTML me hum onclick="handleClick()" likhte the (all lowercase, string me call). React me:

  • Events camelCase me likhe jaate hain: onClick, onChange, onSubmit.
  • Tu function call nahi pass karta, Function Reference pass karta hai: onClick={handleClick} (paranthesis () mat lagana, varna render hote hi chal jayega!).
  • Agar parameter bhejna hai, toh arrow function use karo: onClick={() => handleDelete(item.id)}.
EventsDemo.jsxEvent Handling Patterns
function EventDemo() {
    const handleClick = (e) => {
        console.log("Synthetic Event:", e);
        console.log("Clicked Element:", e.target);
    };

    const handleParam = (userId) => {
        alert("Deleting user: " + userId);
    };

    return (
        <div>
            <button onClick={handleClick}>Click Me (Normal)</button>
            <button onClick={() => handleParam(101)}>Delete User #101</button>
        </div>
    );
}
9. Conditional Rendering: 4 Real-World Tarike
📌 9.1 Kab kya screen par dikhana hai
ConditionalRendering.jsxAll 4 Methods
function AuthStatus({ isLoggedIn, userRole, unreadCount }) {
    // Method 1: Early Return (Guard Clause)
    if (!isLoggedIn) {
        return <div>Please <button>Login</button> to continue.</div>;
    }

    return (
        <div>
            <h2>Welcome back!</h2>

            // Method 2: Ternary Operator (if-else in JSX)
            <p>Role: {userRole === "admin" ? "👑 Admin Access" : "👤 Standard User"}</p>

            // Method 3: Logical AND && (Show if true, show nothing if false)
            {unreadCount > 0 && <span className="badge">🔔 {unreadCount} New Messages</span>}

            // ⚠️ TRAP ALERT: Never do `count && <p>...</p>` if count can be 0!
            // Because `0 && ...` prints the number `0` on screen! Always use `count > 0 && ...`!
        </div>
    );
}
10. Rendering Lists Using map()
📌 10.1 For loop kyu nahi aur map() kyu?

JSX ke curly braces { ... } ke andar standard for loop nahi chal sakta kyunki for ek statement hai jo koi value return nahi karta. JavaScript ka array.map() har item ke badle ek naya JSX element return karta hai, isliye React me list render karne ke liye 100% map() use hota hai!

ProductList.jsxmap() List Rendering
const products = [
    { id: "p1", name: "MacBook Air M2", price: 99999, inStock: true },
    { id: "p2", name: "Sony WH-1000XM5", price: 29999, inStock: false },
    { id: "p3", name: "Keychron K2 Keyboard", price: 8499, inStock: true }
];

function ProductCatalog() {
    return (
        <div className="catalog">
            <h2>Available Gadgets</h2>
            <ul>
                {products.map((item) => (
                    <li key={item.id} style={{ opacity: item.inStock ? 1 : 0.5 }}>
                        <strong>{item.name}</strong> ── ₹{item.price.toLocaleString('en-IN')}
                        {!item.inStock && <span style={{ color: 'red', marginLeft: '10px' }}>(Out of Stock)</span>}
                    </li>
                ))}
            </ul>
        </div>
    );
}
11. Keys and Why They Matter (The Index Trap)
📌 11.1 Aadhar Card vs Roll Number
🚨 The Index as Key Disaster

Maan le ek todo list hai: [0: Brush teeth, 1: Take bath, 2: Have breakfast]. Har item ke aage ek checkbox hai.
Tune pehla item (Brush teeth) delete kar diya! Ab 'Take bath' index 0 ban gaya! React sochega: *"Arey index 0 pehle se ticked tha, toh main naye wale item ka checkbox bhi ticked hi rakhunga!"* Natija: Galat checkbox tick ho jayega aur data corrupt!

KeyRules.jsxKey Rules
// ❌ DANGEROUS: Using index as key in dynamic lists
{items.map((item, index) => <TodoItem key={index} {...item} />)}

// ❌ DANGEROUS: Random keys create and destroy DOM on every single re-render!
{items.map((item) => <TodoItem key={Math.random()} {...item} />)}

// ✅ PRODUCTION RULE: Stable, Unique Primary Key from Database / UUID
{items.map((item) => <TodoItem key={item.id} {...item} />)}
🛠️ Module 2 Practical Lab: Interactive Todo App with State, Events & Filtering

Neeche complete runnable interactive Todo application hai jisme addition, deletion, toggle status, aur filter counts sab shamil hai:

src/TodoApp.jsxComplete Interactive App
import React, { useState } from 'react';

export default function TodoApp() {
    const [todos, setTodos] = useState([
        { id: 1, text: "Revise React Module 1 & 2", completed: true },
        { id: 2, text: "Build Todo App from scratch", completed: false },
        { id: 3, text: "Practice Sudheer J interview Q&As", completed: false }
    ]);
    const [inputValue, setInputValue] = useState("");

    // 1. Add new todo
    const handleAddTodo = (e) => {
        e.preventDefault();
        if (!inputValue.trim()) return;

        const newTodo = {
            id: Date.now(), // Unique stable timestamp ID
            text: inputValue.trim(),
            completed: false
        };

        setTodos(prev => [...prev, newTodo]);
        setInputValue("");
    };

    // 2. Toggle completed status
    const handleToggle = (id) => {
        setTodos(prev => prev.map(todo => 
            todo.id === id ? { ...todo, completed: !todo.completed } : todo
        ));
    };

    // 3. Delete todo
    const handleDelete = (id) => {
        setTodos(prev => prev.filter(todo => todo.id !== id));
    };

    const completedCount = todos.filter(t => t.completed).length;

    return (
        <div style={{ maxWidth: '600px', margin: '40px auto', padding: '24px', background: '#fff', border: '2.5px solid #0f172a', borderRadius: '16px', boxShadow: '5px 5px 0px #0f172a' }}>
            <h2 style={{ marginTop: 0 }}>📝 Pro Todo Manager</h2>
            <p style={{ color: '#64748b' }}>Done: {completedCount} / {todos.length} completed</p>

            <form onSubmit={handleAddTodo} style={{ display: 'flex', gap: '10px', marginBottom: '20px' }}>
                <input 
                    type="text" 
                    value={inputValue}
                    onChange={(e) => setInputValue(e.target.value)}
                    placeholder="What needs to be done?"
                    style={{ flex: 1, padding: '10px 14px', fontSize: '18px', border: '2px solid #0f172a', borderRadius: '8px' }}
                />
                <button type="submit" style={{ padding: '10px 20px', background: '#0284c7', color: '#fff', border: '2px solid #0f172a', borderRadius: '8px', cursor: 'pointer', fontWeight: 'bold' }}>
                    Add Task
                </button>
            </form>

            <ul style={{ listStyle: 'none', padding: 0 }}>
                {todos.map(todo => (
                    <li key={todo.id} style={{ display: 'flex', alignItems: 'center', justifyContent: 'space-between', padding: '12px', borderBottom: '1px solid #e2e8f0' }}>
                        <span 
                            onClick={() => handleToggle(todo.id)}
                            style={{ textDecoration: todo.completed ? 'line-through' : 'none', color: todo.completed ? '#94a3b8' : '#0f172a', cursor: 'pointer', fontSize: '20px' }}
                        >
                            {todo.completed ? '✅' : '⚪'} {todo.text}
                        </span>
                        <button onClick={() => handleDelete(todo.id)} style={{ background: '#fee2e2', border: '1px solid #ef4444', color: '#dc2626', borderRadius: '6px', padding: '4px 10px', cursor: 'pointer' }}>
                            Delete
                        </button>
                    </li>
                ))}
            </ul>
        </div>
    );
}
💼 Module 2 Interview Bank (Sudheer J Style)
State vs Props Fresher / 4-6 LPA

Q: What is the difference between State and Props in React? Can a Child component modify Props?

Answer: Props are inputs passed from a parent component down to a child component; they are strictly immutable (read-only) and the child cannot modify them. State is a component's private, internal data managed by useState; it is mutable using its setter function. When state changes, the component and its children re-render.
State Updates High Frequency

Q: Why does calling setCount(count + 1) three times inside an event handler only increase count by 1?

Answer: Due to closures and batching. In that render's scope, the count variable is captured with its current value (e.g. 0). All three calls execute setCount(0 + 1). The last call overwrites previous ones, setting count to 1. To fix this, use the functional update form: setCount(prev => prev + 1), which queues updates against the latest pending state.
Keys Trap Senior / 8-10 LPA

Q: Why should you never use the array index as a 'key' prop when rendering dynamic lists?

Answer: React uses key to identify which items have changed, been added, or been removed. If items are reordered, inserted at the beginning, or deleted, their array indices change. React assumes the item at that index is the same component as before, reusing its existing DOM node and uncontrolled input state, leading to silent bugs, misplaced text inputs, and performance degradation.
