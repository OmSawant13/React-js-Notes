2. Context API & The Provider Pattern
📌 2.1 createContext & useContext

React ka native Context API low-to-medium frequency updates (jaise Theme, Authentication state, Language/i18n) ke liye built-in solution hai:

AuthContext.jsxContext Provider Pattern
import React, { createContext, useContext, useState } from 'react';

const AuthContext = createContext();

export function AuthProvider({ children }) {
    const [user, setUser] = useState(null);

    const login = (userData) => setUser(userData);
    const logout = () => setUser(null);

    return (
        
            {children}
        
    );
}

// Custom hook to consume context safely
export function useAuth() {
    const context = useContext(AuthContext);
    if (!context) throw new Error("useAuth must be used inside AuthProvider!");
    return context;
}
⚠️ Context API Re-render Trap

Jab bhi Context Provider ki value badalti hai, us context ko consume karne wale saare components bina kisi shart ke re-render hote hain! Isliye high-frequency data (jaise live stock prices, animations, heavy form state) ke liye Context API use mat karo—wahan Redux Toolkit ya Zustand use karo!

3. Redux Fundamentals & Redux Toolkit (RTK)
📌 3.1 The 3 Core Principles of Redux
  1. Single Source of Truth: Poori app ka global state ek single JavaScript object store ke andar rehta hai.
  2. State is Read-Only: State ko badalne ka sirf ek hi tareeqa hai: Ek Action dispatch karo (a plain object describing what happened).
  3. Changes are made with Pure Reducer Functions: Reducer ek pure function hoti hai jo `(previousState, action) => newState` calculate karti hai bina side-effects ke.
📌 3.2 Why Redux Toolkit (RTK) is Modern Standard

Pehle Redux me 40 boilerplate files banani padti thi. Redux Toolkit ne aakar sab aasan kar diya:

  • configureStore(): Automatically DevTools aur Thunk middleware setup kar deta hai.
  • createSlice(): Actions aur Reducers ko ek hi jagah combine kar deta hai.
  • Immer.js Integration: Reducers ke andar direct state.count++ ya state.items.push(item) likh sakte ho! Behind the scenes Immer automatically ek naya immutable state produce karta hai!
4. useSelector & useDispatch
📌 4.1 State Read karna aur Action Bhejna
  • useSelector(state => state.cart.items): Store se specific data nikaalta hai aur component ko us data ke sath subscribe karta hai.
  • useDispatch(): Dispatcher function deta hai jisse hum action trigger karte hain: dispatch(addToCart(product)).
5. Async State Management with `createAsyncThunk`
📌 5.1 Pending, Fulfilled, Rejected Lifecycles

Backend API se data laane ke liye RTK createAsyncThunk deta hai jo automatically 3 action types generate karta hai:

productSlice.jscreateAsyncThunk Pattern
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';
import axios from 'axios';

// 1. Async Thunk
export const fetchProducts = createAsyncThunk(
    'products/fetchProducts',
    async (_, { rejectWithValue }) => {
        try {
            const res = await axios.get('/api/products');
            return res.data;
        } catch (err) {
            return rejectWithValue(err.response.data);
        }
    }
);

// 2. Slice with extraReducers
const productSlice = createSlice({
    name: 'products',
    initialState: { items: [], loading: false, error: null },
    reducers: {},
    extraReducers: (builder) => {
        builder
            .addCase(fetchProducts.pending, (state) => {
                state.loading = true;
                state.error = null;
            })
            .addCase(fetchProducts.fulfilled, (state, action) => {
                state.loading = false;
                state.items = action.payload;
            })
            .addCase(fetchProducts.rejected, (state, action) => {
                state.loading = false;
                state.error = action.payload || "Failed to load products";
            });
    }
});

export default productSlice.reducer;

🛠️ Module 6 Practical Lab: Shopping Cart State Management with Redux Toolkit

Neeche complete runnable shopping cart implementation hai: Store configuration, Cart Slice with Immer mutations, Add to Cart, Remove, Quantity increment, and Total calculation:

src/cartSlice.js & CartComponent.jsxComplete RTK Implementation
// 1. src/features/cartSlice.js
import { createSlice, configureStore } from '@reduxjs/toolkit';

const cartSlice = createSlice({
    name: 'cart',
    initialState: {
        items: [] // { id, name, price, quantity }
    },
    reducers: {
        addToCart: (state, action) => {
            const existing = state.items.find(i => i.id === action.payload.id);
            if (existing) {
                existing.quantity += 1; // 👈 Immer allows direct mutation!
            } else {
                state.items.push({ ...action.payload, quantity: 1 });
            }
        },
        removeFromCart: (state, action) => {
            state.items = state.items.filter(i => i.id !== action.payload);
        },
        clearCart: (state) => {
            state.items = [];
        }
    }
});

export const { addToCart, removeFromCart, clearCart } = cartSlice.actions;

// Configure Global Store
export const store = configureStore({
    reducer: {
        cart: cartSlice.reducer
    }
});

💼 Module 6 Interview Bank (Sudheer J Style)
Redux Core Senior / 8-10 LPA

Q: Why does Redux Toolkit allow writing mutable code like `state.items.push()` inside reducers?

Answer: Redux Toolkit uses Immer.js under the hood. Immer wraps the state in a Proxy. When you write "mutative" code like `state.count++` or `state.items.push(item)`, Immer records all operations on a "draft state" and produces a brand new, pristine, deeply-immutable state object behind the scenes, preventing manual spreading bugs.
Architecture High Frequency

Q: What is the main difference between Client State and Server State? Should you put API cache in Redux?

Answer: Client State is ephemeral UI data owned completely by the browser (modals open/closed, current dark mode theme, draft form values). Server State is remote data persisted in databases (users, products, orders); it is asynchronous, shared, and can become stale. Modern industry architecture discourages storing raw API data in Redux; instead, dedicated server-state tools like TanStack Query (React Query) or RTK Query are used for automatic caching, background refetching, and deduplication.
Context vs Redux Core Concept

Q: Why is Context API not a complete replacement for Redux or Zustand in large applications?

Answer: Context API lacks fine-grained selector subscriptions. Whenever any property in a Context Provider's value object changes, every single component subscribed to that context re-renders, causing massive performance bottlenecks in high-frequency state updates. Redux and Zustand use selective subscriptions (`useSelector(state => state.foo)`), re-rendering only the components whose specific slice changed.
