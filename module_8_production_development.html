2. Authentication with JWT: Access & Refresh Token Rotation Flow
📌 2.1 The Seamless 401 Interceptor Flow
🔬 Production JWT Token Rotation Mechanics SECURITY ARCHITECTURE
1. Access Token: Short-lived (15 minutes). Stored in memory or Authorization Bearer header.
2. Refresh Token: Long-lived (7-30 days). Stored in secure `httpOnly` cookie (XSS immune).
3. User triggers API ──▶ Server responds `401 Unauthorized` (Access Token expired).
4. Axios Response Interceptor catches 401 ──▶ Calls `/api/auth/refresh` endpoint silently.
5. Server verifies refresh cookie ──▶ Returns fresh Access Token.
6. Interceptor updates Authorization header ──▶ Replays original failed API request!
Result: Zero user interruption! User never gets logged out while active!
src/services/api.jsProduction Axios Interceptor
import axios from 'axios';

const api = axios.create({
    baseURL: import.meta.env.VITE_BACKEND_URL || 'http://localhost:5000/api',
    withCredentials: true // Sends httpOnly cookies automatically!
});

// Response Interceptor for Token Rotation
api.interceptors.response.use(
    (response) => response,
    async (error) => {
        const originalRequest = error.config;

        // If 401 and request hasn't been retried yet
        if (error.response?.status === 401 && !originalRequest._retry) {
            originalRequest._retry = true;

            try {
                // Call refresh endpoint to get fresh token
                const refreshRes = await axios.post('/api/auth/refresh', {}, { withCredentials: true });
                const newAccessToken = refreshRes.data.accessToken;

                // Update authorization header and replay
                originalRequest.headers['Authorization'] = `Bearer ${newAccessToken}`;
                return api(originalRequest);
            } catch (refreshErr) {
                // Refresh token expired or revoked -> redirect to login
                window.location.href = '/login';
                return Promise.reject(refreshErr);
            }
        }
        return Promise.reject(error);
    }
);

export default api;

import { useState, useEffect } from 'react';
import axios from 'axios';

export function useJobs(searchTerm, selectedCategory, page = 1) {
    const [jobs, setJobs] = useState([]);
    const [totalPages, setTotalPages] = useState(1);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
        const controller = new AbortController();
        setLoading(true);
        setError(null);

        const params = {
            search: searchTerm || undefined,
            category: selectedCategory !== 'ALL' ? selectedCategory : undefined,
            page,
            limit: 6
        };

        axios.get('http://localhost:5000/api/jobs', { params, signal: controller.signal })
            .then(res => {
                setJobs(res.data.jobs || res.data.data);
                setTotalPages(res.data.totalPages || 1);
                setLoading(false);
            })
            .catch(err => {
                if (err.name !== 'CanceledError' && err.name !== 'AbortError') {
                    setError(err.message);
                    setLoading(false);
                }
            });

        return () => controller.abort();
    }, [searchTerm, selectedCategory, page]);

    return { jobs, totalPages, loading, error };
}

Debounce vs Throttle Senior / 10-12 LPA

Q: What is the exact difference between Debouncing and Throttling? Give real frontend examples.

Answer: Debouncing bunches a series of sequential events and delays execution until after a specified period of inactivity (e.g., executing a search query only after the user stops typing for 400ms). Throttling guarantees that a function is executed at most once per specified time interval, regardless of how many times the event fires (e.g., updating a progress indicator on infinite window scroll or resizing every 100ms).
JWT Security Enterprise Security

Q: Where should you store JWT access tokens in a React frontend? LocalStorage or Memory?

Answer: Never store sensitive JWT access tokens in `localStorage` or `sessionStorage` in high-security applications because any third-party script or Cross-Site Scripting (XSS) vulnerability can access them via JavaScript. The enterprise standard is to keep the short-lived access token in JavaScript in-memory state (or closure/context) and store the long-lived refresh token in an httpOnly, secure, sameSite=strict cookie which JavaScript cannot read, eliminating token theft via XSS.
Testing Production Standard

Q: What is the core philosophy of React Testing Library (RTL) vs Enzyme?

Answer: "The more your tests resemble the way your software is used, the more confidence they can give you." Enzyme focused on testing internal implementation details (component state, internal method calls, shallow rendering). React Testing Library focuses on testing user behavior from the user's perspective (finding elements by accessible text/role, firing clicks, and asserting visible screen output), ensuring tests don't break during refactoring if behavior remains unchanged.
