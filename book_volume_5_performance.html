1. Performance Tuning: Re-render Triggers, React.memo & Virtualization
📌 1.1 The 4 Reasons a React Component Re-renders
  1. State Update: A component's own state changed via setState().
  2. Parent Re-render: When a parent component renders, by default ALL its child components re-render recursively, regardless of whether their props changed!
  3. Props Update: New prop values passed from parent.
  4. Context Update: Any component calling useContext(MyContext) will re-render whenever the context provider's value changes.
🔬 Bio-Anatomy: Breaking React.memo via Referential Inequality MEMOIZATION GOTCHA
ParentComponent renders:
const config = { theme: 'dark' }; // ❌ Brand new object reference on EVERY render!
const handleClick = () => {}; // ❌ Brand new function reference on EVERY render!
─────────────────────────────────────────────────────────────────────────────
<MemoizedChild config={config} onClick={handleClick} />
React.memo compares:
prevProps.config === nextProps.config ──▶ FALSE! (Different memory addresses)
prevProps.onClick === nextProps.onClick ──▶ FALSE! (Different memory addresses)
Result: <MemoizedChild /> RE-RENDERS ANYWAY! React.memo was completely useless!
─────────────────────────────────────────────────────────────────────────────
✅ FIX: Wrap config in useMemo() and handleClick in useCallback()!
⚡ 1.2 List Virtualization (Windowing): Rendering 100,000 Rows

If you render 100,000 items in standard React, the browser creates 100,000 physical DOM nodes, consuming 800MB of RAM and freezing scrolling. Virtualization renders only the 15–20 items currently visible in the user's viewport, recycling DOM nodes dynamically as the user scrolls.

VirtualList.jsxreact-window Pattern
import { FixedSizeList as List } from "react-window";

const Row = ({ index, style }) => (
    <div style={style} className="list-row">
        Row #{index}: Fast 60FPS Virtualized DOM node
    </div>
);

function LargeDataset() {
    return (
        <List
            height={500}         // Viewport height in px
            itemCount={100000}   // 1 Lakh items
            itemSize={45}         // Row height in px
            width={"100%"}
        >
            {Row}
        </List>
    );
}

Q: When should you NOT use React.memo?

Key Answer: Do not wrap components in React.memo if: 1. The component is very simple/cheap to render (the shallow prop comparison check costs more CPU than just letting it re-render). 2. The component’s props change almost every single render anyway (you pay the cost of shallow comparison PLUS the render cost). 3. The component takes children or un-memoized object/function props, which breaks shallow equality every time.
