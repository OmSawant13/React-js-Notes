1. useState: Fiber Memoized State, Functional Updates & Auto-Batching
📌 1.1 How useState Persists State Across Renders

A functional component is just a plain JavaScript function. When it finishes running, its local variables are garbage collected. How does useState remember its value across re-renders? Internally, React Fiber nodes maintain a singly linked list of Hook objects attached to fiber.memoizedState. Each hook call advances an internal index pointer. This is the exact reason for the Rules of Hooks: Hooks must NEVER be called inside loops, conditions, or nested functions, because doing so alters the linked list pointer sequence!

⚡ REACT 18 AUTOMATIC BATCHING:
Before React 18: Multiple setState() inside promises or setTimeout() triggered multiple re-renders.
React 18+: ALL state updates are grouped into ONE SINGLE re-render tick automatically!
setTimeout(() => {
setCount(c => c + 1);
setFlag(f => !f);
// Triggers EXACTLY 1 re-render, NOT 2!
}, 100);
💻 1.2 Practical Code: Stale State Trap vs Functional Update
useState_patterns.jsxReact Runnable
function Counter() {
    const [count, setCount] = useState(0);

    // ⚠️ STALE CLOSURE TRAP:
    const handleBadIncrement = () => {
        setCount(count + 1);
        setCount(count + 1);
        setCount(count + 1);
        // Result: count is 1, NOT 3! Because 'count' was captured as 0 in this render scope!
    };

    // ✅ SAFE FUNCTIONAL UPDATE:
    const handleGoodIncrement = () => {
        setCount(prev => prev + 1);
        setCount(prev => prev + 1);
        setCount(prev => prev + 1);
        // Result: count is 3! Each update reads the freshly queued pending state.
    };

    // 🚀 LAZY INITIAL STATE (Avoids re-running heavy computations on every re-render):
    const [cachedData] = useState(() => {
        return JSON.parse(localStorage.getItem("heavy_data")) || [];
    });

    return <button onClick={handleGoodIncrement}>Count: {count}</button>;
}
2. useEffect: Dependencies, Cleanup Execution & Race Conditions
📌 2.1 The Purpose & Timing of useEffect

useEffect allows you to perform side effects (data fetching, subscriptions, manual DOM mutations, timer intervals) in functional components. Crucially, useEffect executes asynchronously AFTER the browser has completed painting the screen, ensuring side effects do not block user interface responsiveness.

⚡ 2.2 Network Race Conditions & AbortController

If a user rapidly clicks between User #1 and User #2, request #1 might return after request #2 due to network latency, overwriting the screen with stale data (a Race Condition). Use AbortController in the cleanup function to cancel pending network requests.

UserProfile_race_condition_safe.jsxProduction Pattern
function UserProfile({ userId }) {
    const [user, setUser] = useState(null);

    useEffect(() => {
        const controller = new AbortController(); // Native browser abort signal

        async function fetchProfile() {
            try {
                const res = await fetch(`/api/users/${userId}`, { signal: controller.signal });
                const data = await res.json();
                setUser(data);
            } catch (err) {
                if (err.name !== "AbortError") {
                    console.error("Fetch failed:", err);
                }
            }
        }
        fetchProfile();

        // CLEANUP FUNCTION: Runs before the next effect runs OR when component unmounts!
        return () => {
            controller.abort(); // Cancels in-flight network request cleanly
        };
    }, [userId]); // Re-runs effect whenever userId prop changes

    if (!user) return <p>Loading profile...</p>;
    return <h2>{user.name}</h2>;
}
3. useMemo & useCallback: Referential Equality & Memoization Cost
📌 3.1 The Distinction
  • useMemo(() => computeValue(a, b), [a, b]): Caches the result value of an expensive function.
  • useCallback(fn, [deps]): Caches the function definition itself to maintain referential equality across renders.
⚠️ 3.2 The Premature Optimization Trap

Every useMemo and useCallback call incurs an overhead: allocating a dependency array, checking equality of each dependency on every render, and keeping values in memory. Do NOT wrap trivial calculations in useMemo (e.g. const total = useMemo(() => a + b, [a, b]) is slower than recalculating!). Use them ONLY for genuinely expensive loops or when passing callbacks to children wrapped in React.memo.

4. useRef & forwardRef: Mutable State without Re-renders
📌 4.1 Two Main Use Cases of useRef
  1. Accessing Real DOM Elements: Managing focus, triggering media playback, measuring dimensions.
  2. Storing Mutable State without Re-rendering: Keeping track of timer IDs, previous prop values, or render counts.
forwardRef_example.jsxDOM Forwarding Pattern
const CustomInput = React.forwardRef((props, ref) => {
    return <input ref={ref} className="styled-input" {...props} />;
});

function LoginForm() {
    const inputRef = useRef(null);

    const handleFocus = () => {
        inputRef.current.focus(); // Directly interact with underlying DOM node
    };

    return (
        <>
            <CustomInput ref={inputRef} placeholder="Enter username" />
            <button onClick={handleFocus}>Focus Input</button>
        </>
    );
}

6. React 18 Concurrent Hooks: useTransition & useDeferredValue
📌 6.1 Urgent vs Transition Updates

In React 18, updates are categorized into:

  • Urgent Updates: Direct interactions (typing, clicking, hovering) that demand instant responsiveness.
  • Transition Updates: Secondary UI updates (rendering a list of 5,000 filtered results).
useTransition_demo.jsxReact 18 Non-Blocking Search
function SearchDashboard() {
    const [input, setInput] = useState("");
    const [list, setList] = useState([]);
    const [isPending, startTransition] = useTransition();

    const handleChange = (e) => {
        // Urgent update: Update input field immediately (zero input lag!)
        setInput(e.target.value);

        // Non-urgent transition: React can interrupt this if user types another letter!
        startTransition(() => {
            const filtered = generateThousandsOfItems(e.target.value);
            setList(filtered);
        });
    };

    return (
        <>
            <input value={input} onChange={handleChange} placeholder="Instant filter..." />
            {isPending ? <p>Filtering list in background...</p> : <ItemList items={list} />}
        </>
    );
}
7. Custom Hooks: Encapsulating Reusable State & Logic
📌 7.1 Production Custom Hook: useDebounce

Debouncing delays invoking a function until after a specific duration has elapsed since the last call. Essential for search bars to prevent spamming backend APIs with requests on every keystroke.

hooks/useDebounce.jsReusable Production Hook
import { useState, useEffect } from "react";

export function useDebounce(value, delayMs = 500) {
    const [debouncedValue, setDebouncedValue] = useState(value);

    useEffect(() => {
        const handler = setTimeout(() => {
            setDebouncedValue(value);
        }, delayMs);

        return () => {
            clearTimeout(handler); // Cancel previous timer if value changes within delayMs
        };
    }, [value, delayMs]);

    return debouncedValue;
}
